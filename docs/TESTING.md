# الاختبارات

## 1. Backend — `cd backend && npm test`

لا تحتاج PostgreSQL محليًا: اختبارات e2e تشغّل **PostgreSQL 17 حقيقيًا داخل الذاكرة (PGlite)** في عملية منفصلة، وتطبق نفس ملفات الـmigration، ثم تشغّل تطبيق NestJS كاملًا عبر HTTP (supertest). مزود الـPush مستبدل بنسخة تسجل الإشعارات ويمكن برمجتها لتفشل.

| الملف | يغطي |
|---|---|
| `test/auth.e2e-spec.ts` | PIN صحيح/خاطئ/صيغة خاطئة، حساب معطل، Cookie آمن، عدم إظهار الـPIN، تحديد المعدل، CSRF (ترويسة + Origin)، تسجيل الخروج، التعطيل الفوري، **استبدال الجهاز**، المتصفح المشترك، مصفوفة **RBAC** لكل الأدوار |
| `test/requests.e2e-spec.ts` | عامل واحد / عدة عمال / الجميع، بدون صورة / صورة / 3 صور / رفض الرابعة، رفض PDF (حتى بامتداد jpg)، رفع idempotent، **منع التكرار** (3 طلبات متزامنة ⇒ طلب واحد)، فتح ← استلام ← تنفيذ بأوقات الخادم، حالة مستقلة لكل عامل، عزل الصور بين العمال، تعديل (عنوان، صور، ترتيب)، إلغاء، إعادة إرسال، إعادة فتح، عزل طلبات المدراء، البحث والفلاتر والتاريخ والصفحات، لوحة التحكم |
| `test/notifications.e2e-spec.ts` | محتوى الإشعار، إشعار مستقل لكل طلب، بدون اشتراك ⇒ SKIPPED، **اشتراك منتهٍ 410 ⇒ تنظيف**، إعادة المحاولة بالـbackoff (حد 3)، التذكير كل 5 دقائق (حد 3)، إيقاف التذكير بعد الفتح، الإعدادات، إيصال التسليم، إشعارات التعديل/الإلغاء/إعادة الفتح، الجهاز المفصول، استبدال الجهاز |
| `test/offline-sync.e2e-spec.ts` | إعادة تشغيل عمليات Offline بالترتيب، التكرار بلا أثر، الطلبات المتزامنة، **تعارض: إلغاء من المدير**، **تعارض: إعادة فتح بعد تنفيذ Offline قديم**، المزامنة التزايدية، طلبات وصلت أثناء انقطاع العامل |
| `test/users.e2e-spec.ts` | إنشاء/تعديل/تعطيل/تفعيل/حذف ناعم للعمال، تغيير PIN، تفرد الـPIN بين كل الحسابات، الصورة، إدارة المدراء، حماية آخر مدير نظام، النبض (متصل/آخر اتصال)، سجل الدخول، **منع حذف سجل العمليات من قاعدة البيانات** |
| `src/**/*.spec.ts` | آلة حالات العامل، معالجة الصور (الصيغ، الأبعاد، إزالة EXIF، رفض غير الصور)، تحويل أخطاء Web Push، إعدادات البيئة، الـPIN HMAC، الإعدادات |

```bash
npm test                  # الكل (118 اختبارًا)
npm run test:unit         # unit فقط
npm run test:e2e          # e2e فقط
npm run test:migrations   # تطبيق الـmigrations على PostgreSQL داخل الذاكرة + فحص القيود
```

## 2. Frontend — `cd web && npm test`

Vitest + Testing Library + IndexedDB وهمي:
- `offline/worker-sync.test.ts`: الحالة المحلية، الطابور Offline، الإرسال بالترتيب مع سلسلة الإصدارات، التعارض (إلغاء)، 5xx/401، النقر المزدوج، المزامنة التزايدية مع الإبقاء على العمليات المعلقة.
- `offline/outbox.test.ts`: إرسال المدير مع الصور، الحفظ Offline، **انقطاع أثناء الرفع ثم الاستكمال دون إعادة رفع**، الأخطاء النهائية.
- `lib/api.test.ts`: ترويسة CSRF، رسائل الأخطاء العربية، أخطاء الشبكة، تنسيق الأوقات بالثواني.
- `components/components.test.tsx`: شارات الحالة، شاشة الدخول بالـPIN.

`npm run build` يشغّل فحص TypeScript الكامل قبل البناء.

## 3. متصفح حقيقي على النظام الكامل — `cd e2e && npm install && npm test`

يتطلب: `backend` و`web` مبنيين (`npm run build` في كل منهما) وGoogle Chrome مثبتًا. يشغّل PostgreSQL داخل الذاكرة + الـmigrations + بيانات التطوير + الخادم الحقيقي، ثم Chrome بملفين منفصلين: مدير (سطح مكتب) وعامل (هاتف 390×844).

يتحقق من: الـmanifest، ترويسات الـService Worker والأمان، دخول العامل وتحكم الـService Worker، إرسال طلب بصورة، منع التكرار بالنقر المزدوج، ظهور الطلب بوضوح لدى العامل مع الصورة، «تم الاستلام» وظهوره **لحظيًا** لدى المدير، «تم التنفيذ» **بدون إنترنت** وظهور «بانتظار المزامنة»، **إعادة تحميل التطبيق بدون إنترنت** (app shell + بيانات محفوظة)، المزامنة عند عودة الاتصال، صفحات العامل، جدول العمال والسجل، **تخطيط الجوال** (القائمة الجانبية المنزلقة وعدم التمرير الأفقي)، صفحات مدير النظام، منع المدير من صفحات الإدارة.

الصور في `e2e/screenshots/`. `E2E_HEADED=1` يشغّل نافذة Chrome حقيقية (خارج الشاشة).

> **ملاحظة:** Chrome المؤتمت لا يستقبل Web Push (لا توجد خدمة Push في الوضع الآلي)، لذا خطوتا الإشعار «اختياريتان» في هذا الاختبار. تم التحقق بشكل منفصل من أن خدمة FCM تقبل الإشعار المرسل من الخادم (HTTP 201)، ويبقى التحقق النهائي على هاتف حقيقي.
